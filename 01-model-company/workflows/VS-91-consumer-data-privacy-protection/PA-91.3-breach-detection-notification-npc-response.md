## W3057. Personal Data Breach Detection, Triage & Incident Activation

| Field | Detail |
|---|---|
| **Trigger** | Suspected breach signal (SIEM alert, report, anomaly) |
| **Frequency** | Event-driven |
| **Volume** | Varies; majority false-positive |
| **Owner** | IT Security Manager |
| **Participants** | IT Security, DPO, SOC, Customer Service, LP |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | IT Security/SOC detect potential breach via monitoring (links to VS-27); log incident; perform initial triage and severity scoring | IT Security / SOC | IT Security Manager | <1 hr |
| 2 | IT Security/DPO assess whether incident constitutes a reportable personal-data breach (confidentiality/integrity/availability of personal data); activate incident response if yes | IT Security / DPO | DPO | <24 hr |
| 3 | DPO activates breach response team (IT Security, Legal, Comms, HR, Customer Service, executive); appoint incident commander; start 72-hour clock for NPC notification (W3059) | DPO | DPO | Per activation |

### System Touchpoints
- SIEM/SOC (links to VS-27); incident response case; breach response playbook

### Pain Points / Risks
- **Detection-delay risk**: Breach undetected, eroding notification window; mitigated by monitoring and triage SLA


### Automation Opportunity
- System auto-log of "IT Security/SOC detect potential breach via monitoring" (replaces manual Step 1).
- System auto-report of "reportable personal-data breach" (replaces manual Step 2).

### Controls
- CTL-504 (ensure controlled execution — Breach Detection, Notification & NPC Regulatory Response (PA-91.3).)
- operational: monitoring and triage SLA

### Time Estimate
- <24 hr to activate

## W3058. Breach Containment, Forensic Investigation & Scope Assessment

| Field | Detail |
|---|---|
| **Trigger** | Breach confirmed |
| **Frequency** | Per incident |
| **Volume** | Per incident |
| **Owner** | IT Security Manager |
| **Participants** | IT Security, DPO, Legal, Forensics, affected Business Process Owners |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | IT Security contains breach (isolate systems, revoke access, reset credentials, patch); preserves forensic evidence and logs | IT Security | IT Security Manager | Immediate |
| 2 | Forensics/IT Security investigate root cause, entry vector, and timeline; determine data categories, volume, and subjects affected | Forensics / IT Security | IT Security Manager | Per incident |
| 3 | DPO/Business Process Owners assess scope using ROPA (W3042): which data, how many subjects, sensitivity, and likely harm; feeds notification decisions | DPO / Process Owners | DPO | Per incident |

### System Touchpoints
- Forensic tooling/evidence preservation; ROPA (W3042); incident case

### Pain Points / Risks
- **Scope-uncertainty risk**: Under/over-stating affected subjects; mitigated by ROPA-driven scoping and forensics


### Automation Opportunity
- System auto-log of "IT Security contains breach" (replaces manual Step 1).
- System auto-flag for investigation of "investigate root cause, entry vector, and timeline" (replaces manual Step 2).

### Controls
- CTL-504 (ensure controlled execution — Breach Detection, Notification & NPC Regulatory Response (PA-91.3).)
- operational: ROPA-driven scoping and forensics

### Time Estimate
- Hours to days

## W3059. NPC Breach Notification (72-Hour) & Regulatory Reporting

| Field | Detail |
|---|---|
| **Trigger** | Reportable breach confirmed |
| **Frequency** | Per reportable breach |
| **Volume** | Subset of incidents |
| **Owner** | Data Protection Officer (DPO) |
| **Participants** | DPO, Legal, IT Security, Compliance, Records |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | DPO/Legal prepare NPC breach notification (nature, data categories, approximate subjects, likely harm, measures taken) within 72 hours of knowledge where required | DPO / Legal | DPO | <72 hr |
| 2 | DPO submits notification to NPC per prescribed format/channel; coordinates any law-enforcement notification (cybercrime, PNP-ACG) where applicable | DPO | DPO | <72 hr |
| 3 | Records/Legal retain breach documentation per VS-88; support NPC follow-up inquiries and supplementary reports as scope refines | Records / Legal | DPO | Per incident |

### System Touchpoints
- NPC notification template/channel; records retention (links to VS-88); incident case

### Pain Points / Risks
- **Late-notification risk**: Missing 72-hour window triggers penalties; mitigated by activation-to-notification playbook and templates


### Automation Opportunity
- System auto-generate of "prepare NPC breach notification" (replaces manual Step 1).
- System auto-submit of "submits notification to NPC per prescribed format/channel" (replaces manual Step 2).
- System auto-record of "Records/Legal retain breach documentation per VS-88" (replaces manual Step 3).

### Controls
- CTL-504 (ensure controlled execution — Breach Detection, Notification & NPC Regulatory Response (PA-91.3).)
- operational: activation-to-notification playbook and templates

### Time Estimate
- <72 hr

## W3060. Affected Data Subject Notification & Remediation

| Field | Detail |
|---|---|
| **Trigger** | Breach likely to cause harm to subjects |
| **Frequency** | Per qualifying breach |
| **Volume** | Up to affected subjects (could be large for loyalty/ecommerce breach) |
| **Owner** | Data Protection Officer (DPO) |
| **Participants** | DPO, Comms, Customer Service, Legal, IT |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | DPO/Comms draft subject notification (what happened, data involved, harm, remediation, contact); Legal reviews; calibrate to NPC guidance | DPO / Comms / Legal | DPO | Per breach |
| 2 | Comms/Customer Service deliver notification to affected subjects via appropriate channel; staff dedicated support hotline/chat; log inquiries | Comms / Customer Service | Marketing Communications Manager | Per breach |
| 3 | IT/DPO provide remediation (credit-monitoring equivalent, password reset, fraud-alert guidance, free identity-protection where offered); track remediation uptake | IT / DPO | DPO | Per breach |

### System Touchpoints
- Customer communication (links to VS-13/VS-14); incident case; remediation tracking

### Pain Points / Risks
- **Reputational risk**: Poor notification damages trust; mitigated by timely, transparent, supportive communication


### Automation Opportunity
- System auto-review of "DPO/Comms draft subject notification" (replaces manual Step 1).
- System auto-log of "Comms/Customer Service deliver notification to affected subjects via appropriate" (replaces manual Step 2).
- System auto-track of "track remediation uptake" (replaces manual Step 3).

### Controls
- CTL-504 (ensure controlled execution — Breach Detection, Notification & NPC Regulatory Response (PA-91.3).)
- operational: timely, transparent, supportive communication

### Time Estimate
- Per breach; ongoing support
