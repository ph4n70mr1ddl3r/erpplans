## W2286. Order Source Selection Engine

| Field | Detail |
|---|---|
| **Trigger** | Customer places order |
| **Frequency** | ~46,400 orders/month |
| **Volume** | ~46,400 routing decisions/month |
| **Owner** | Ecommerce Operations Manager |
| **Participants** | Ecom Ops Manager |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | System evaluates per line item: nearest store, DC, vendor drop-ship, dark store; selects by speed, cost, availability, item type; BOPIS → customer-selected store; delivery → fastest+cheapest | System | Ecom Ops Manager | <5 sec automated |

### System Touchpoints
- Order management / routing engine (links to VS-08 / W536 unified order management, W534 multi-origin fulfillment) — the source-selection logic
- ATP / inventory (links to VS-05 / W105 multi-channel allocation, VS-60 / W2306 visibility) — the real-time availability per source
- Ecommerce platform (links to VS-10 / W11 BOPIS, W98 order exception) — the order-intake

### Pain Points / Risks
- **Suboptimal-routing risk**: the engine picks a fast-but-costly source when a cheaper-but-slightly-slower source would do, eroding margin; mitigated by the cost-optimization feedback in W2293 and the engine weight-tuning
- **ATP-inaccuracy risk**: the engine routes to a source whose ATP is stale (sync lag), causing a post-reservation stock-out; mitigated by the W2306 sync-accuracy monitoring and the <30 min sync SLA

### Automation Opportunity
- Routing fully automated; A/B test of weight-changes before production (W2304)

### Controls
- CTL-44 (reservation integrity); CTL (ATP accuracy — links to VS-05); operational: Ecom Ops Manager routing-rule sign-off

### Time Estimate
~5 sec/decision automated; Ecom Ops Manager rule-tuning ~4 hours/month = **~50 hours/year** human, system handles the volume.

### Controls
- CTL-44 (sub-order integrity); operational: Ecom Ops Manager split-rate monitoring

### Time Estimate
Automated; Ecom Ops Manager ~4 hours/month monitoring = **~50 hours/year**.

### Steps

### System Touchpoints
- Store fulfillment (links to VS-07 / W19B ship-from-store, VS-04 picking) — the pick/pack/label

- **Pick-error risk**: the Associate picks the wrong item/SKU, causing a customer return; mitigated by the barcode-scan verification at pick and the W2300 quality control

### Automation Opportunity
- Pick list auto-generated with barcode-verify; 3PL pickup auto-scheduled; tracking auto-updated

### Controls
- CTL-44 (pick/ATP integrity); CTL-24 (pick-fraud detection); operational: Store Manager ship-from-store-volume oversight

### Time Estimate
~22 min/order × ~10,000/month = **~3,700 hours/month Stock Associate** (absorbed into store-ops, volume-capped).

- Drop-ship PO (links to VS-03 / W246 drop-ship back-to-back PO, VS-10 / W246 ecommerce) — the PO to the vendor with the customer address

- Drop-ship PO auto-generated; vendor-confirmation auto-tracked with escalation; delivery auto-tracked

### Controls
- CTL-44 (drop-ship PO integrity); CTL (revenue-recognition-at-delivery — links to VS-157); operational: Vendor Coordinator monitoring

### Time Estimate
~1.5 days/order coordination × ~3,000/month (mostly automated) = **~60 hours/month Vendor Coord + Finance** (the 3–7 day delivery is vendor-side, not BuildRight labor).

### System Touchpoints
- ATP / reservation (links to VS-05 / W105 multi-channel allocation, W56 backorder) — the reservation logic
- Inventory (links to VS-05 / W6 cycle counting) — the reserved vs. available split
- Omnichannel sync (links to VS-60 / W2306) — the real-time reservation across channels

### Pain Points / Risks
- **Double-sell risk**: two channels reserve the same unit simultaneously (sync lag), causing an over-promise; mitigated by the atomic-reservation (single authoritative ATP) and the W2306 sync monitoring

### Automation Opportunity
- Reservation fully automated with atomic-ATP; expiry auto-processed

### Controls
- CTL-44 (reservation integrity); CTL (atomic-ATP — no double-sell); operational: Inventory Manager reservation-expiry review

### Time Estimate
Automated; Inventory Manager ~4 hours/month monitoring = **~50 hours/year**.

## W2291. Order Routing Exception Management

| Field | Detail |
|---|---|
| **Trigger** | Routing failure |
| **Frequency** | ~2K–3K exceptions/month (~5%) |
| **Volume** | ~2K–3K/month |
| **Owner** | Ecommerce Operations Manager |
| **Participants** | Ecom Ops Manager, VP Marketing |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | System detects: stock-out after reservation, store unable to fulfill, vendor rejection; Manager re-routes to alternative source; communicates revised timeline; systemic issues to IT | System / Ecom Ops Manager | VP Marketing | 15–30 min/exception |

### System Touchpoints
- Exception management (links to VS-10 / W98 ecommerce order exception, W2291) — the exception detection and re-route
- Customer comms (links to VS-13 / W56 backorder notification) — the revised-timeline communication
- IT incident (links to VS-27 / W48 helpdesk) — the systemic-issue escalation

### Pain Points / Risks
- **Exception-cascade risk**: a stock-out triggers a re-route that also fails (cascading exceptions), exhausting the alternatives; mitigated by the exception-depth-limit (after 2 re-routes, offer the customer substitute/cancel)
- **Customer-experience-degradation risk**: each exception adds delay and a revised-timeline message, eroding trust; mitigated by the exception-rate target (<5%) and the root-cause fix for systemic issues

### Automation Opportunity
- Exception auto-detected; re-route auto-suggested; customer-comms auto-sent; systemic-pattern auto-flagged to IT

### Controls
- CTL-44 (re-route integrity); operational: Ecom Ops Manager exception-rate review; VP Marketing escalation on >5% rate

### Time Estimate
~20 min/exception × ~2,500/month = **~830 hours/month Ecom Ops Manager** (distributed across the ops team, not one person).

## W2293. Order Routing Cost Optimization

| Field | Detail |
|---|---|
| **Trigger** | Monthly cost analysis |
| **Frequency** | Monthly |
| **Volume** | ~46,400 routed orders |
| **Owner** | Logistics Finance Analyst |
| **Participants** | Finance Manager |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Calculates fulfillment cost per channel; identifies cost-optimized routing patterns; recommends rule adjustments; tests in simulation before production | Logistics Finance Analyst | Finance Manager | 4–6 hours/month + 2–3 hours |

### System Touchpoints
- Cost analytics (links to VS-28 / W113, VS-61 / W2325 fleet TCO, VS-158 / W85) — the per-channel fulfillment cost
- Routing engine (links to VS-60 / W2286, W2304 algorithm optimization) — the rule-adjustment target
- Simulation (links to VS-30 / W398 PoC) — the test-before-production

### Pain Points / Risks
- **Cost-vs-speed-trade-off risk**: cost-optimization routes to the cheapest source, lengthening delivery time and hurting customer experience; mitigated by the cost-and-SLA joint view (not cost alone)
- **Simulation-vs-production-divergence risk**: the simulation validates a rule change but production behaves differently (real-world variability); mitigated by the canary-release (rule change to 5% of traffic first)

### Automation Opportunity
- Cost-per-channel auto-computed; rule-change-impact auto-simulated

### Controls
- CTL-409 (ensure controlled execution — Intelligent Order Routing (PA-60.1).)
- CTL (cost-accuracy — links to VS-158); operational: Finance Manager sign-off on rule changes; Ecom Ops Manager canary-release sign-off

### Time Estimate
~5 hours/month + ~2.5 hours simulation = **~90 hours/year** Logistics Finance Analyst.
