## W2158. Daily Gift Card Liability Reconciliation

| Field | Detail |
|---|---|
| **Trigger** | End-of-day POS close and ecommerce settlement |
| **Frequency** | Daily across 200 stores + ecommerce |
| **Volume** | ~15,000–25,000 daily GC transactions |
| **Owner** | Accountant (AP/AR) |
| **Participants** | Accountant, Finance Manager |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Accountant reconciles the daily gift-card liability movement: openings + loads/reloads − redemptions − breakage − cancellations = closing; validates the stored-value-system total against the GL liability account | Accountant | Finance Manager | 1–2 hours/day |

### System Touchpoints
- Stored-value ledger (links to VS-08 / W28, VS-54 / W2143/2150) — the daily movement
- GL reconciliation (links to VS-17 / W9A, W89 bank reconciliation pattern) — the stored-value-vs-GL match
- POS/ecommerce settlement (links to VS-08 / W541 cash office, VS-10) — the transaction source

### Pain Points / Risks
- **Unreconciled-difference risk**: the stored-value total and the GL don't tie, indicating a posting error or a missing transaction; mitigated by the daily reconciliation catching the discrepancy within 24 hours (not month-end)
- **Timing-cut risk**: the reconciliation's cut-off misaligns with the stored-value-system batch, creating a false discrepancy; mitigated by the aligned cut-off (reconciliation runs after the stored-value batch completes)

### Automation Opportunity
- Reconciliation auto-run with discrepancy auto-flagged; GL auto-tied to the stored-value total

### Controls
- CTL-44 (liability-reconciliation integrity); CTL-89 (bank/liability reconciliation — links to VS-17); operational: Finance Manager daily sign-off

### Time Estimate
~1.5 hours/day × 30 days = **~45 hours/month Accountant**.

## W2160. Gift Card Fraud Monitoring & Prevention

| Field | Detail |
|---|---|
| **Trigger** | Real-time alerts or weekly review |
| **Frequency** | Real-time + weekly comprehensive |
| **Volume** | ~50–100 flagged transactions/week; <0.5% fraud |
| **Owner** | Loss Prevention Analyst |
| **Participants** | LP Analyst, Loss Prevention Mgr |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | System applies real-time fraud rules: velocity (rapid high-value purchases), enumeration (brute-force card-number attempts), geolocation anomalies, stolen-payment-method patterns; holds suspicious transactions for review | System / LP Analyst | Loss Prevention Mgr | Real-time |
| 2 | LP Analyst reviews the flagged queue weekly: confirms fraud (reverse the transaction, freeze the card), or releases the hold (false positive); tunes the rules to reduce false positives | LP Analyst | Loss Prevention Mgr | 4–6 hours/week |

### System Touchpoints
- Fraud monitoring (links to VS-125 / W266 ecommerce fraud, VS-23 / W248 inventory variance) — the fraud-rule engine and the flagged queue
- Stored-value (links to VS-08 / W28) — the freeze and reversal
- Payment gateway (links to VS-80 / W537) — the stolen-payment detection

### Pain Points / Risks
- **False-positive-customer-harm risk**: legitimate high-value purchases are held, frustrating good customers; mitigated by the false-positive review SLA and the rule-tuning in step 2
- **Novel-fraud-pattern risk**: a new fraud pattern (e.g., a card-number leak) isn't caught by the existing rules; mitigated by the VS-125 fraud-intelligence feed and the rule-refresh

### Automation Opportunity
- Fraud-rules auto-applied in real-time; false-positive-rate auto-monitored for rule-tuning

### Controls
- CTL (fraud-detection — links to VS-125); CTL-44 (freeze/reversal integrity); operational: Loss Prevention Manager weekly sign-off

### Time Estimate
~5 hours/week LP Analyst = **~250 hours/year**.

## W2161. Gift Card Program ROI Analysis

| Field | Detail |
|---|---|
| **Trigger** | Quarterly program review |
| **Frequency** | Quarterly; annual comprehensive |
| **Volume** | ~PHP 500–600M annual liability; ~PHP 30–50M breakage |
| **Owner** | FP&A Analyst |
| **Participants** | CFO |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | FP&A Analyst computes the program ROI: program cost (card production, platform, fraud loss, marketing) vs. program benefit (breakage revenue, incremental basket lift from gift-card recipients, cash-flow float benefit); recommends the program-investment split | FP&A Analyst | CFO | 2–3 days/quarter |

### System Touchpoints
- FP&A / cost accounting (links to VS-17 / W26, VS-158 / W85) — the cost and benefit inputs
- Breakage (links to VS-54 / W2156) — the breakage-revenue benefit
- Basket analytics (links to VS-13 / W17, VS-28 / W113) — the gift-card-recipient basket-lift

### Pain Points / Risks
- **Benefit-attribution risk**: the "incremental basket lift" (gift-card recipients spend more than the card value) is hard to attribute cleanly; mitigated by the loyalty-tagged gift-card-redemption basket analysis
- **Breakage-dependency risk**: the ROI over-relies on breakage revenue, which is ethically and regulatorily sensitive (consumer-protection scrutiny of unused balances); mitigated by the ROI presented with and without breakage, so the program stands on the basket-lift alone

### Automation Opportunity
- ROI auto-assembled from the cost/benefit datasets; basket-lift auto-computed from loyalty-tagged redemptions

### Controls
- CTL-393 (ensure controlled execution — Gift Card Reconciliation & Analytics (PA-54.3).)
- CTL (ROI/budget accuracy — links to VS-17); operational: CFO sign-off on the ROI methodology

### Time Estimate
~2.5 days/quarter = **~80–100 hours/year** FP&A Analyst.

### System Touchpoints
- API gateway (links to VS-27 / W257 enterprise API lifecycle) — the 4 integrations
- Stored-value platform (links to VS-08 / W28) — the integrated system
- IT monitoring (links to VS-27 / W380 alert & event management) — the API-health monitoring

### Pain Points / Risks
- **API-degradation risk**: a slow/degraded API causes checkout friction (redemption fails or times out); mitigated by the real-time health monitoring and the failover (if the stored-value API is down, the POS caches and reconciles later per the offline-resilience pattern)
- **Integration-asymmetry risk**: the app integration lags the POS integration (new features ship to POS first), creating inconsistent experience; mitigated by the synchronized release across all 4 integrations

### Automation Opportunity
- API-health auto-monitored with auto-ticketing on degradation; integrations auto-tested on release

### Controls
- CTL-393 (ensure controlled execution — Gift Card Reconciliation & Analytics (PA-54.3).)
- CTL (API/integration integrity — links to VS-27); operational: CIO monthly sign-off

### Time Estimate
~6 hours/week IT Integration Lead = **~300 hours/year**.

- Channel platforms (links to VS-08, VS-10, VS-75, VS-11) — the 4 channels
- Analytics (links to VS-28 / W113) — the channel-performance dataset

### Pain Points / Risks
- **Cost-allocation arbitrariness risk**: the platform/IT cost allocation across channels is arbitrary, distorting the per-channel profitability; mitigated by the transaction-volume-based allocation (the channels driving the most transactions bear the IT cost)
- **Cross-channel-cannibalization blindness**: a channel grows by shifting volume from another (not net growth); mitigated by the total-program view alongside the channel view

### Automation Opportunity
- Channel-profitability auto-computed quarterly with cost-allocation documented

### Controls
- CTL-393 (ensure controlled execution — Gift Card Reconciliation & Analytics (PA-54.3).)
- CTL (cost-allocation accuracy); operational: CFO sign-off on the analysis

### Time Estimate
~2 days/quarter = **~60–80 hours/year** FP&A Analyst.
