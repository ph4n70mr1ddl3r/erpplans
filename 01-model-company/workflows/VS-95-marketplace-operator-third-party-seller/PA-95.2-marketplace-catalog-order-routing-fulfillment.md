## W3145. Unified Marketplace Catalog & Search Merchandising

| Field | Detail |
|---|---|
| **Trigger** | Continuous catalog ops; search-relevance review |
| **Frequency** | Continuous + monthly review |
| **Volume** | ~10K–50K 3P SKUs + 35K 1P SKUs unified |
| **Owner** | Marketplace Manager |
| **Participants** | Marketplace Mgr, Catalog Ops (links to VS-01/VS-10), Ecommerce (links to VS-10), BI (links to VS-28) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Catalog Ops merge 1P and 3P offers into unified catalog per product taxonomy (links to VS-01); each SKU page may show 1P offer + multiple 3P offers with buy-box logic (W3146) | Catalog Ops | Marketplace Manager | Continuous |
| 2 | Ecommerce tune search relevance: combine title/spec/keyword/category; boost by listing quality (W3140), seller performance (W3154), conversion, and sponsorship (links to VS-48 retail media); apply merchandising rules (featured, new arrivals, top-rated) | Ecommerce / BI | Marketplace Manager | Monthly |
| 3 | Marketplace Mgr monitors catalog health: duplicate listings, miscategorization, prohibited items (links to W3156 policy), price anomalies, out-of-date content; remediate with sellers | Marketplace Mgr / Seller Ops | Marketplace Manager | Continuous |

### System Touchpoints
- Unified catalog/search (links to VS-10/VS-29); retail-media boosting (links to VS-48); listing-quality score (W3140)

### Pain Points / Risks
- **Search-clutter risk**: Duplicate/spammy listings degrade discovery; mitigated by dedup rules and quality gating


### Automation Opportunity
- System auto-log of "log Ops merge 1P and 3P offers into unified catalog per product taxonomy" (replaces manual Step 1).
- System auto-monitor of "monitors catalog health" (replaces manual Step 3).

### Controls
- CTL-515 (ensure controlled execution — Marketplace Catalog, Order Routing & Seller Fulfillment (PA-95.2).)
operational: dedup rules and quality gating

### Time Estimate
- Continuous; ~monthly tuning

## W3146. First-Party vs Third-Party Offer Comparison & Buy-Box

| Field | Detail |
|---|---|
| **Trigger** | Offer change; buy-box recompute |
| **Frequency** | Continuous (real-time) |
| **Volume** | All multi-offer SKUs |
| **Owner** | Marketplace Manager |
| **Participants** | Marketplace Mgr, Ecommerce (links to VS-10), Category (links to VS-01), Finance |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | System computes buy-box winner per multi-offer SKU using weighted algorithm: total price (item + shipping + tax), seller performance (W3154), fulfillment speed, in-stock, returns policy; surfaces "Other Sellers" panel for runners-up | System | Marketplace Manager | Real-time |
| 2 | Category (links to VS-01) sets 1P/3P rules: categories where 1P wins by policy (private label — links to VS-41, controlled brands), categories open to 3P, and categories where 3P complements 1P (vendor direct-ship for out-of-stock) | Category Manager | VP Merchandising | Per category |
| 3 | Marketplace Mgr monitor buy-box distribution: 1P share vs. 3P share, seller diversity, price competitiveness; flag anomalies (price war, seller dominance) and adjust rules | Marketplace Mgr / BI | Marketplace Manager | Weekly |

### System Touchpoints
- Buy-box engine; pricing master (links to VS-01); seller performance (links to W3154)

### Pain Points / Risks
- **Self-preferencing risk**: Always favoring 1P attracts competition-law scrutiny; mitigated by transparent, performance-based algorithm and documented rules


### Automation Opportunity
- System auto-monitor of "monitor buy-box distribution" (replaces manual Step 3).

### Controls
- CTL-515 (ensure controlled execution — Marketplace Catalog, Order Routing & Seller Fulfillment (PA-95.2).)
operational: transparent, performance-based algorithm and documented rules

### Time Estimate
- Continuous; weekly review

## W3147. Marketplace Order Capture, Fraud Screening & Routing

| Field | Detail |
|---|---|
| **Trigger** | Customer places marketplace order |
| **Frequency** | Continuous |
| **Volume** | Per marketplace order |
| **Owner** | Marketplace Manager |
| **Participants** | Marketplace Mgr, Ecommerce (links to VS-10), Fraud/LP (links to VS-23), Seller Operations |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Ecommerce (links to VS-10) captures order; for multi-seller basket (W3149) splits into per-seller sub-orders; reserves seller inventory (W3150); computes total price incl. shipping, tax, fees | Ecommerce / System | Marketplace Manager | Per order |
| 2 | Fraud/LP (links to VS-23) screen order: payment fraud, fake/compromised account, first-party fraud, promo abuse (links to W3152); velocity rules, device fingerprint, address risk; hold/cancel/review suspicious orders | Fraud Analyst / System | Marketplace Manager | Per order (real-time) |
| 3 | Marketplace routes sub-order to seller (or to BuildRight fulfillment — Fulfilled-by-BuildRight — links to VS-93) with fulfillment SLA, shipping label, customer address; seller acknowledges and begins fulfillment (W3148) | System / Seller | Marketplace Manager | Per order |

### System Touchpoints
- Order capture (links to VS-10/VS-60); fraud screening (links to VS-23); seller routing; reservation (W3150)

### Pain Points / Risks
- **Marketplace fraud risk**: Higher than 1P; mitigated by multi-signal fraud screening and seller vetting (W3138)


### Automation Opportunity
- System auto-capture of "captures order" (replaces manual Step 1).
- System auto-generate of "print, address risk" (replaces manual Step 2).
- System auto-route of "routes sub-order to seller" (replaces manual Step 3).

### Controls
- CTL-86 (ensure marketplace seller & tax compliance.)
operational: multi-signal fraud screening and seller vetting (W3138)

### Time Estimate
- Per order (automated)

## W3148. Seller Fulfillment SLA, Shipment Tracking & POD

| Field | Detail |
|---|---|
| **Trigger** | Seller accepts sub-order |
| **Frequency** | Per order |
| **Volume** | Per marketplace order |
| **Owner** | Marketplace Manager |
| **Participants** | Marketplace Mgr, Seller, Carrier/3PL (links to VS-56), CS (links to VS-13) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Seller fulfills per SLA (e.g., ship within 24–48 hr); for BuildRight-fulfilled (links to VS-93), follow dark-store/DC dispatch SLA; generate carrier label, manifest, hand-off to carrier | Seller / Carrier | Marketplace Manager | Per order |
| 2 | System captures tracking events (carrier API — links to VS-56); push to customer (links to VS-10/VS-13); on delivery, capture POD/e-signature; auto-close order on confirmed delivery | System / Carrier | Marketplace Manager | Per order |
| 3 | Marketplace Mgr monitor SLA adherence (ship-on-time %, delivery-on-time %, cancellation rate, late-ship rate); under-performers flagged in seller scorecard (W3154) and remediation/penalty path | Marketplace Mgr / Seller Ops | Marketplace Manager | Daily |

### Pain Points / Risks
- **Late-ship risk**: Seller SLA breach hurts customer experience; mitigated by SLA monitoring, penalty, and Fulfill-by-BuildRight option


### Automation Opportunity
- System auto-generate of "generate carrier label, manifest, hand-off to carrier" (replaces manual Step 1).
- System auto-track of "tracking events" (replaces manual Step 2).
- System auto-monitor of "monitor SLA adherence" (replaces manual Step 3).

### Controls
- CTL-515 (ensure controlled execution — Marketplace Catalog, Order Routing & Seller Fulfillment (PA-95.2).)
operational: SLA monitoring, penalty, and Fulfill-by-BuildRight option

### Time Estimate
- Per order; ~daily review

## W3150. Seller Inventory Sync, Reservation & Oversell Prevention

| Field | Detail |
|---|---|
| **Trigger** | Seller inventory change; order reservation; sync failure |
| **Frequency** | Continuous (real-time) |
| **Volume** | All 3P listings |
| **Owner** | Marketplace Manager |
| **Participants** | Marketplace Mgr, IT, Seller, Ecommerce (links to VS-10) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Seller maintains inventory via API (real-time), bulk upload, or portal; system syncs to listing availability; quality rules for stale feeds (auto-delist if feed > 24 hr stale) | Seller / IT | Marketplace Manager | Continuous |
| 2 | On order placement: system atomically reserves seller inventory; on oversell (concurrent orders exceed available): cancel, offer back-order, or substitute per seller policy; refund customer if cancelled (links to VS-80) | System | Marketplace Manager | Per order |
| 3 | IT monitor sync health: API uptime, feed freshness, reservation accuracy; alert on anomalies; reconcile against seller reported inventory weekly | IT / Seller Ops | Marketplace Manager | Daily/weekly |

### System Touchpoints
- Seller inventory API; reservation engine; ecommerce availability (links to VS-10); refunds (links to VS-80)

### Pain Points / Risks
- **Oversell risk**: Stale inventory causes cancellation and customer dissatisfaction; mitigated by real-time sync, atomic reservation, and stale-feed delisting


### Automation Opportunity
- System auto-sync of "syncs to listing availability" (replaces manual Step 1).
- System auto-monitor of "monitor sync health" (replaces manual Step 3).

### Controls
- CTL-515 (ensure controlled execution — Marketplace Catalog, Order Routing & Seller Fulfillment (PA-95.2).)
operational: real-time sync, atomic reservation, and stale-feed delisting

### Time Estimate
- Continuous monitoring

## W3151. Marketplace Returns, Seller Responsibility & Disposition

| Field | Detail |
|---|---|
| **Trigger** | Customer initiates marketplace return |
| **Frequency** | Per return (~5–10% return rate) |
| **Volume** | Per marketplace order |
| **Owner** | Marketplace Manager |
| **Participants** | Marketplace Mgr, Seller, CS (links to VS-13), Quality, AP (links to VS-15) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | CS (links to VS-13) log return request with reason; route to seller; per marketplace policy decide approval (auto-approve for low-value, seller-review for high-value); communicate decision to customer | CS / Seller | Marketplace Manager | Per return |
| 2 | Customer ships item back (to seller or BuildRight consolidation per policy); on receipt, seller inspects, files dispute if item not as returned; CS mediates disputes | Customer / Seller / CS | Marketplace Manager | Per return |
| 3 | On approval: refund customer (links to VS-80) and debit seller settlement (W3153); item disposition (restock by seller, refurbish — links to VS-09, dispose per VS-73); track return rate per seller to scorecard (W3154) | Finance / Seller | Marketplace Manager | Per return |

### System Touchpoints
- Returns workflow (links to VS-32); refund (links to VS-80); settlement debit (links to W3153/VS-15)

### Pain Points / Risks
- **Return-abuse risk**: Fake returns, item-swap; mitigated by inspection, evidence capture, and serial tracking (links to VS-23)


### Automation Opportunity
- System auto-log of "log return request with reason" (replaces manual Step 1).
- System auto-inspect of "inspects, files dispute if item not as returned" (replaces manual Step 2).
- System auto-track of "track return rate per seller to scorecard" (replaces manual Step 3).

### Controls
- CTL-515 (ensure controlled execution — Marketplace Catalog, Order Routing & Seller Fulfillment (PA-95.2).)
operational: inspection, evidence capture, and serial tracking (links to VS-23)

### Time Estimate
- 5–10 days per return cycle
