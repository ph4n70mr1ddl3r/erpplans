## W3241. Software & License Entitlement Inventory

| Field | Detail |
|---|---|
| **Trigger** | Continuous discovery; reconciliation; audit (W3246) |
| **Frequency** | Continuous + quarterly reconciliation |
| **Volume** | Full software estate: OS, applications, SaaS, cloud |
| **Owner** | Software Asset Manager |
| **Participants** | Software Asset Mgr, IT Ops (links to VS-27), Procurement (links to VS-34), Legal, Finance |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Software Asset Mgr maintain software inventory: discovery of installed software (agent scan per W3233), usage telemetry; entitlement inventory (purchased licenses, subscriptions, cloud commitments) from contracts/POs (links to VS-34); reconcile installations vs entitlements to detect over/under-licensing | Software Asset Mgr / IT Ops | Software Asset Manager | Continuous |
| 2 | Classify and normalize the software catalog: publisher, product, version/edition, metric (per-device, per-user, per-core, concurrent, consumption), license model (perpetual, subscription, SaaS, open-source), contract reference, renewal date, owner; build product-use hierarchy | Software Asset Mgr | Software Asset Manager | Quarterly |
| 3 | Reconcile to finance (links to VS-17/VS-34.3) and procurement (links to VS-34): match entitlements to POs and invoices, ensure software spend correctly capitalized (perpetual) vs expensed (subscription/SaaS); flag orphan entitlements (paid but unused) | Software Asset Mgr / Finance | Software Asset Manager | Quarterly |

### System Touchpoints
- Discovery/SAM tool (links to VS-27); procurement (links to VS-34); GL (links to VS-17); CMDB (W3233)

### Pain Points / Risks
- **Inventory-blindness risk**: Unknown/unmanaged software (shadow IT, links to VS-27.3); mitigated by discovery and normalization
- **Metric-misunderstanding risk**: Wrong licensing metric causes true-up exposure (W3246); mitigated by entitlement mastery


### Automation Opportunity
- System auto-scan of "scan per W3233" (replaces manual Step 1).
- System auto-log of "Classify and normalize the software catalog" (replaces manual Step 2).
- System auto-reconcile of "Reconcile to finance" (replaces manual Step 3).

### Controls
- CTL-143 (ensure IT asset & license entitlement integrity.)
- operational: discovery and normalization; operational: entitlement mastery

### Time Estimate
- Continuous; 1–2 weeks/quarterly reconciliation

## W3242. License Optimization, Reharvesting & Reconciliation

| Field | Detail |
|---|---|
| **Trigger** | Quarterly optimization; renewal (W3245); cost-reduction initiative |
| **Frequency** | Quarterly + event-driven |
| **Volume** | Full estate |
| **Owner** | Software Asset Manager |
| **Participants** | Software Asset Mgr, IT Ops (links to VS-27), User Depts, Procurement, Finance |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Software Asset Mgr analyze usage vs entitlement: identify unused/under-used licenses (installed-not-used, inactive users), over-deployed products (installation > entitlement — compliance risk W3246), and right-sizing opportunities (edition down-grade, metric change) | Software Asset Mgr / IT Ops | Software Asset Manager | Quarterly |
| 2 | Reharvest and reallocate: reclaim licenses from inactive/departed users (coordinate HR per VS-19.5), reassign to new users instead of new purchase, uninstall unauthorized/redundant software, consolidate overlapping tools; reduce true-up liability | Software Asset Mgr / IT Ops / User Depts | Software Asset Manager | Quarterly |
| 3 | Optimize licensing model: convert perpetual-to-subscription (or vice-versa) where economic, negotiate enterprise agreements (W3245), adopt concurrent/use-based metrics, standardize on fewer products; track savings vs target | Software Asset Mgr / Procurement / Finance | Software Asset Manager | Quarterly |

### System Touchpoints
- SAM/discovery (links to VS-27); HR feed (links to VS-19); procurement (links to VS-34); finance (links to VS-17)

### Pain Points / Risks
- **Over-licensing waste**: Paying for unused licenses; mitigated by usage analytics and reharvesting
- **Under-licensing exposure**: Installing beyond entitlement → true-up/audit liability (W3246); mitigated by reconciliation and remediation


### Automation Opportunity
- System auto-analyze of "analyze usage vs entitlement" (replaces manual Step 1).
- System auto-assign of "reassign to new users instead of new purchase, uninstall unauthorized/redundant…" (replaces manual Step 2).
- System auto-capture of "enterprise agreements" (replaces manual Step 3).

### Controls
- CTL-143 (ensure IT asset & license entitlement integrity.)
- operational: usage analytics and reharvesting; operational: reconciliation and remediation

### Time Estimate
- Quarterly; 1–2 weeks/cycle

## W3247. Open Source License Compliance & Security

| Field | Detail |
|---|---|
| **Trigger** | New build/release (links to VS-27.1 W132); policy review; vulnerability alert |
| **Frequency** | Continuous + per release |
| **Volume** | Open-source components in custom apps, ERP integrations |
| **Owner** | Software Asset Manager |
| **Participants** | Software Asset Mgr, Development (links to VS-27.1), Security (links to VS-27.3), Legal |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Software Asset Mgr/Dev (links to VS-27.1 W132) maintain software bill of materials (SBOM) for custom applications and integrations: scan code for open-source components and their licenses (permissive, copyleft/GPL, weak-copyleft); inventory versions and direct/transitive dependencies | Software Asset Mgr / Dev | Software Asset Manager | Per release |
| 2 | Legal/Dev review license obligations: copyleft (GPL/AGPL) obligations (source disclosure, derivative-work licensing) may conflict with proprietary distribution — avoid or isolate; attribution/notices for permissive (MIT/Apache/BSD); ensure compliance with each license's terms | Legal / Dev | VP Legal & Compliance | Per component |
| 3 | Security (links to VS-27.3) track open-source vulnerabilities (CVEs) in components, remediate via patch/upgrade (links to W3250), monitor for new advisories; integrate SCA (software composition analysis) into CI/CD (links to VS-27.1 W132); report license/security posture | Security / Dev | Software Asset Manager | Continuous |

### System Touchpoints
- SBOM/SCA tooling (links to VS-27.1); security (links to VS-27.3); development (links to VS-27.1 W132)

### Pain Points / Risks
- **Copyleft-contamination risk**: GPL/AGPL components force source disclosure of proprietary code; mitigated by license review and architectural isolation
- **Vulnerable-component risk**: Known CVEs in open-source are a major attack vector; mitigated by SCA and patching (W3250)


### Automation Opportunity
- System auto-scan of "scan code for open-source components and their licenses" (replaces manual Step 1).
- System auto-review of "review license obligations" (replaces manual Step 2).
- System auto-track of "track open-source vulnerabilities" (replaces manual Step 3).

### Controls
- CTL-527 (ensure controlled execution — Software Asset Management & License Compliance (PA-99.2).)
- operational: license review and architectural isolation; operational: SCA and patching (W3250)

### Time Estimate
- Per release; continuous monitoring
