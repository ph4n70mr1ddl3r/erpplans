## W2897. SC/PWD/Solo Parent ID Validation & Eligibility Verification at POS

| Field | Detail |
|---|---|
| **Trigger** | Customer presents discount ID at checkout |
| **Frequency** | ~140,000–225,000 transactions/month (5–8% of POS) |
| **Volume** | 600 POS terminals; 200 stores |
| **Owner** | Store Manager |
| **Participants** | Cashier, Customer, Store Manager |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Cashier validates ID: OSCA Senior ID / PhilSys for seniors; PWD ID from NCDA-accredited LGU; Solo Parent ID from LGU; checks photo, validity, and ownership | Cashier | Store Manager | Per transaction |
| 2 | Cashier captures ID number and customer name in POS; ERP applies statutory discount and records transaction in mandatory-discount register | Cashier | Store Manager | Per transaction |
| 3 | Store Manager resolves disputes (expired ID, eligibility question) per protocol; denies discount with courteous explanation where invalid | Store Manager | Store Manager | Per dispute |

### System Touchpoints
- POS mandatory-discount module; ID validation; discount register

### Pain Points / Risks
- **Compliance risk**: Granting discount without valid ID forfeits tax credit; mitigated by mandatory ID capture in POS

### Time Estimate
- 1–2 min per transaction

## W2898. Mandatory Discount Computation, Stack Rules & Basket Validation

| Field | Detail |
|---|---|
| **Trigger** | Discount applied at POS |
| **Frequency** | Per transaction |
| **Volume** | ~140K–225K transactions/month |
| **Owner** | Pricing Analyst |
| **Participants** | Pricing, IT, Store Ops |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Pricing configures discount rules: 20% SC/PWD (5% for groceries per RA 9994 for selected prime commodities; 32% for medicines under RA 10754 = 20% discount + 12% VAT-exempt); 10% Solo Parent on selected goods/baby items | Pricing | VP Merchandising | Per rule |
| 2 | IT implements stack-prevention logic (cannot combine SC + PWD; cannot combine statutory + promotional beyond allowed); validates eligible-SKU basket | IT | Pricing Analyst | Per rule |
| 3 | Store Ops audits POS application vs. rule monthly; investigates computation errors; corrects configuration | Store Ops | Store Manager | Monthly |

### System Touchpoints
- Discount-rule engine; eligible-SKU mapping; POS audit log

### Pain Points / Risks
- **Compliance risk**: Wrong stack/computation violates law and forfeits credit; mitigated by rule engine and audit

### Time Estimate
- Per-rule configuration; monthly audit

## W2899. SC/PWD Purchase Book of Sales Transaction Recording

| Field | Detail |
|---|---|
| **Trigger** | Each SC/PWD transaction |
| **Frequency** | Continuous; aggregated monthly |
| **Volume** | ~140K–225K transactions/month |
| **Owner** | Tax Accountant |
| **Participants** | Tax Accountant, Store Manager, IT |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | ERP auto-records each SC/PWD transaction in mandatory Book of Sales/Transactions (per RA 9994 IRR): date, customer name, ID number, gross amount, discount, VAT component | ERP automation | Tax Accountant | Per transaction |
| 2 | Tax Accountant validates book completeness monthly per store; reconciles to POS sales register; investigates gaps | Tax Accountant | Tax Manager | Monthly |
| 3 | Tax Accountant archives book per location for BIR inspection; maintains 10-year retention | Tax Accountant | Tax Manager | Monthly |

### System Touchpoints
- Mandatory-discount book register; POS reconciliation; archive

### Pain Points / Risks
- **Compliance risk**: Incomplete book forfeits tax credit and incurs penalty; mitigated by auto-recording and monthly reconciliation

### Time Estimate
- Continuous; 1–2 days/month reconciliation

## W2900. Discount Abuse, ID Sharing & Fraud Prevention Monitoring

| Field | Detail |
|---|---|
| **Trigger** | Anomaly detection or LP review |
| **Frequency** | Weekly review |
| **Volume** | ~50–200 flagged events/month |
| **Owner** | LP Analyst |
| **Participants** | LP, Store Manager, IT |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | IT/LP monitors for fraud signals: same ID used across multiple transactions/stores, frequent high-value purchases, ID photo mismatch | LP Analyst | LP Manager | Weekly |
| 2 | LP investigates flagged events; reviews CCTV; refers suspected ID-sharing/fraud to OSCA/NCDA/PNP where warranted | LP | LP Manager | Per case |
| 3 | Store Manager reinforces cashier vigilance; LP trends abuse by store and recommends controls (ID-scan, frequency caps) | Store Manager / LP | LP Manager | Monthly |

### System Touchpoints
- LP exception monitoring; ID-frequency analytics; CCTV correlation

### Pain Points / Risks
- **Loss risk**: ID-sharing fraud erodes margin (discount not recoverable if invalid); mitigated by monitoring and validation

### Time Estimate
- Continuous; 1–2 days/week

| **Volume** | All stores |
| **Owner** | Customer Service Lead |
| **Participants** | Customer Service, Store Manager, Compliance, Legal |

### Steps

|---|---|---|---|---|

### Time Estimate
