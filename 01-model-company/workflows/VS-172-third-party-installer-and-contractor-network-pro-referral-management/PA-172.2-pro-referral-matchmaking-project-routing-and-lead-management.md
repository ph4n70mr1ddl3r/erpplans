## W4993. Customer "Find-a-Pro" Request Intake, Qualification & Consent

| Field | Detail |
|---|---|
| **Trigger** | Customer requests an installer (online/app/store/after-purchase) |
| **Frequency** | Continuous (200 stores + online) |
| **Volume** | ~3,000–6,000 Find-a-Pro requests/month (national) |
| **Owner** | CX (VS-13) / Pro-Referral Network Manager / Store Ops |
| **Participants** | CX (VS-13), Store Ops (VS-07), Digital (VS-10/VS-75), Privacy/DPO (VS-91), Marketplace (VS-95) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Intake the request: capture the customer's project need (trade/specialty, scope, location, timing, budget), the linked materials/order (links VS-10/VS-11) where applicable, and contact details; qualify the request (real intent, scope clarity) | CX / Counter Staff / Digital | Network Manager / CX Lead | Per request |
| 2 | Capture consent & set expectations: capture consent to share contact/project details with installers (RA 10173 — links VS-91), set expectations (response time, referral-not-guarantee disclaimer, that the installer is an independent contractor not BuildRight's employee), and confirm the referral terms | CX / DPO / Digital | Network Manager / DPO | Per request |
| 3 | Route to matchmaking: qualify-and-route the request to matchmaking (W4994), manage incomplete/invalid requests, and feed demand analytics (W4991) | CX / Marketplace / Analytics | Network Manager | Per request |

### System Touchpoints
- Marketplace/Find-a-Pro (VS-95/VS-10/VS-75); CRM (VS-11/VS-107); privacy/consent (VS-91); CX (VS-13); analytics (VS-28)

### Pain Points / Risks
- **Privacy risk**: Sharing customer data without consent (RA 10173); mitigated by consent capture
- **Mis-expectation risk**: Customer expecting BuildRight guarantees/employment; mitigated by clear disclaimer
- **Lead-quality risk**: Vague/invalid requests waste installer time; mitigated by qualification

### Time Estimate
- ~per-request intake 5–15 min

### Automation Opportunity
- Request-intake forms (online/app); consent capture; qualification rules; auto-route to matchmaking

### Controls
- CTL-747 (ensure controlled execution — Pro-Referral Matchmaking, Project Routing & Lead Management (PA-172.2).)
- CTL-747: consent captured (VS-91); disclaimer set; request qualified; routed to matchmaking

### Cross-references
- links to VS-91 (privacy/consent), VS-10/VS-75 (digital), VS-95 (marketplace), VS-13 (CX), W4991 (demand), W4994 (matchmaking), W4995 (handoff)

## W4994. Installer Matchmaking, Routing & Lead Distribution

| Field | Detail |
|---|---|
| **Trigger** | Qualified request (W4993) |
| **Frequency** | Continuous |
| **Volume** | ~2–4 matches per request × ~3,000–6,000 requests/month |
| **Owner** | Pro-Referral Network Manager / Marketplace (VS-95) / IT |
| **Participants** | Marketplace (VS-95), IT (VS-27), Analytics (VS-28), Installer, CX (VS-13) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Match the request to installers: by trade specialty, service area/location (links VS-29), capacity/availability (W4999), tier (preferred-first W4989), rating (W5003), and pricing fit; produce a ranked shortlist | Marketplace / IT / Analytics / Network Manager | Network Manager | Per request |
| 2 | Distribute the lead: route the lead to the matched installer(s) per the routing model (preferred-first, rotation, or broadcast-auction), with the customer/project details (per consent W4993), and track acceptance/decline | Marketplace / IT / Installer | Network Manager | Per request |
| 3 | Manage routing rules & fairness: tune the routing model for fairness/anti-discrimination (links VS-129), monitor fill-rate and installer-load balance (W4999), and escalate unaccepted leads (W5000) | Network Manager / Analytics / Legal | COO | Continuous |

### System Touchpoints
- Marketplace/matchmaking (VS-95); CRM/lead (VS-11/VS-107); location master (VS-29); analytics (VS-28); privacy (VS-91)

### Pain Points / Risks
- **Mis-match risk**: Wrong trade/area/capacity → poor outcome; mitigated by accurate matching criteria
- **Routing-fairness risk**: Unfair routing favoring some installers (VS-129); mitigated by fair/rotational rules
- **Unaccepted-lead risk**: Installer declines/ignores → unfulfilled referral; mitigated by W5000 recovery

### Time Estimate
- ~per-request matchmaking automated (seconds/minutes)

### Automation Opportunity
- Matchmaking engine (trade/area/capacity/rating); routing-rule engine; acceptance tracking; load-balance alerts

### Controls
- CTL-747 (ensure controlled execution — Pro-Referral Matchmaking, Project Routing & Lead Management (PA-172.2).)
- CTL-747: match criteria accurate; routing fair; lead-acceptance tracked; unaccepted escalated (W5000)

### Cross-references
- links to VS-95 (marketplace), VS-29 (location), VS-129 (fairness), W4989 (tier), W4993 (intake), W4995 (handoff), W4999 (capacity), W5000 (recovery), W5003 (rating)

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|

- **Communication-failure risk**: Poor customer↔installer comms → disputes; mitigated by platform comms and CX support

### Time Estimate
- ~per-lead handoff days (quote cycle)

### Automation Opportunity

### Controls
- CTL-747 (ensure controlled execution — Pro-Referral Matchmaking, Project Routing & Lead Management (PA-172.2).)

## W4997. Referral Fee, Commission & Settlement Management

| Field | Detail |
|---|---|
| **Trigger** | Project booking (W4996); completion (W4998); billing cycle |
| **Frequency** | Per project + billing cycle |
| **Volume** | ~300–600 settlements per month (per completed project) × network |
| **Owner** | Pro-Referral Network Manager / Finance (VS-17/VS-16) |
| **Participants** | Finance (VS-17/VS-16), Installer, Legal (VS-100), Audit (VS-21), Marketplace (VS-95) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Define the referral economics: the referral-fee/commission model (flat per lead, % of project value, % of materials sold, or marketplace transaction fee), the free-vs-charge thresholds, the B2B/contract treatment (VS-11), and the tax (BIR VAT/EWT on installer fees links VS-79) | Finance / Network Manager / Legal / Tax | CFO / COO | Per policy |
| 2 | Calculate & settle: compute the referral fee/commission per completed project (W4998), invoice/collect from the installer (or deduct from marketplace settlement), issue BIR-compliant billing (links VS-79), and reconcile to finance (VS-17/VS-16) | Finance / Marketplace / Tax | Finance Lead | Per project |
| 3 | Govern & audit: monitor fee leakage/revenue assurance (links VS-118), disputes/installer pushback, audit the settlement (VS-21), and refine the economics (W4985) | Finance / Audit / Network Manager | CFO | Continuous |

### System Touchpoints
- Finance/AP-AR (VS-17/VS-16); marketplace settlement (VS-95); tax/BIR (VS-79); revenue assurance (VS-118); analytics (VS-28)

### Pain Points / Risks
- **Revenue-leakage risk**: Fees not collected (VS-118); mitigated by capture-at-completion and reconciliation
- **Tax-compliance risk**: VAT/EWT on installer fees mis-handled (VS-79); mitigated by BIR-compliant billing
- **Dispute risk**: Installer disputes fees; mitigated by clear terms and audit trail

### Time Estimate
- ~per-project settlement automated; ~billing cycle monthly

### Automation Opportunity
- Auto-compute fee on completion; marketplace settlement; BIR-compliant invoicing; revenue-assurance alerts

### Controls
- CTL-98 (ensure installer-network vetting & referral integrity.)
- CTL-747: economics defined; fee captured at completion; BIR-compliant; reconciled; audited (VS-21)

## W5000. Lost/Declined Lead Recovery, Alternate Referral & Demand Capture

| Field | Detail |
|---|---|
| **Trigger** | Lead declined/unaccepted (W4994); quote lost (W4995); installer unavailable |
| **Frequency** | Continuous |
| **Volume** | ~500–1,000 lost/declined leads per month across the network |
| **Owner** | Pro-Referral Network Manager / CX (VS-13) |
| **Participants** | CX (VS-13), Marketplace (VS-95), Analytics (VS-28), Services (VS-12), Installer |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Detect lost/declined leads: monitor unaccepted leads (W4994), lost quotes (W4995), and abandoned requests; flag for recovery within the response SLA | Marketplace / Analytics / CX | Network Manager | Continuous |
| 2 | Recover via alternate referral: re-route to alternate installers (W4994), offer BuildRight's own crews (VS-12) where available, or recommend delivery/alternatives (VS-06/VS-143); keep the customer engaged | CX / Marketplace / Services | Network Manager | Per lead |
| 3 | Capture demand & learn: even if referral fails, capture the project demand (materials sale, financing VS-154, design VS-66), analyze loss reasons (coverage W4991, pricing, capacity), and feed improvement | CX / Analytics / Network Manager | COO | Continuous |

### System Touchpoints
- Marketplace/analytics (VS-95/VS-28); CX (VS-13); services (VS-12); CRM (VS-11); financing (VS-154)

### Pain Points / Risks
- **Lost-referral risk**: Unfulfilled referral → lost attach/CLV; mitigated by recovery
- **Customer-churn risk**: Customer leaves for a competitor; mitigated by fast alternate referral
- **Demand-blindness risk**: Lost demand not captured/learned; mitigated by demand capture & analytics

### Time Estimate
- ~per-lead recovery within SLA (hours/days)

### Automation Opportunity
- Lost-lead auto-flag; auto-re-route; alternate-offer automation; loss-reason analytics

### Controls
- CTL-747 (ensure controlled execution — Pro-Referral Matchmaking, Project Routing & Lead Management (PA-172.2).)
- CTL-747: lost leads detected within SLA; alternate referral offered; demand captured; loss reasons analyzed

### Cross-references
