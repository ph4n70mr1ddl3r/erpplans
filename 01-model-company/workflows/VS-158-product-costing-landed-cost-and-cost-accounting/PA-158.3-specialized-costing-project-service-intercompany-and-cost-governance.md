## W4665. Project / Job Costing for B2B & Government Contracts

| Field | Detail |
|---|---|
| **Trigger** | Project/contract award (VS-11/VS-46); project cost transaction; project close-out |
| **Frequency** | Per project (lifecycle) |
| **Volume** | ~ Active B2B/G2G projects (VS-11.2/VS-46.2); ~30% trade + 10% corporate revenue |
| **Owner** | Cost Accounting Manager / Project Controller |
| **Participants** | Trade/Government sales (VS-11/VS-46), Project Finance (VS-11.2), Procurement (VS-03), Controller |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Set up the project/job cost structure (WBS): material by delivery stage, direct labor, subcontractor, equipment rental, freight to site, project overhead; define the cost-collection method (actual) and the revenue-matching method (W4632) | Project Controller / Cost Accounting | Controller / Trade Sales Mgr | Per project |
| 2 | Collect actual project cost (material issues, AP invoices, timesheets, subcontractor bills, freight) to the project WBS; monitor actual-vs-budget margin (VS-11.2 W918) and flag margin erosion | Project Controller / Cost Accounting / AP | Controller | Per project lifecycle |
| 3 | At project close-out (VS-11.2 W793), compute final project cost and margin, reconcile to revenue recognized (W4632), and feed lessons-learned into future bid costing (VS-11.2 W162) | Project Controller / Cost Accounting | Controller | Per close-out |

### System Touchpoints
- Project/job module (VS-11.2); AP (VS-15); procurement (VS-03); GL (VS-17.1); revenue recognition (VS-157 W4632)

### Pain Points / Risks
- **Cost-miss risk**: Project cost (subcontractor, freight to site) not captured to the WBS understates project cost and overstates project margin; mitigated by WBS-driven cost collection
- **Margin-erosion-blind risk**: Late margin detection prevents corrective action; mitigated by real-time actual-vs-budget monitoring (VS-11.2)

### Time Estimate
- ~per project lifecycle; ~weekly flash + close-out reconciliation

### Automation Opportunity
- WBS-driven auto cost collection from AP/procurement/timesheet; real-time margin dashboard; close-out auto-reconciliation

### Controls
- CTL: project cost collected to WBS; actual-vs-budget monitored weekly; final margin reconciled to revenue at close-out

### Cross-references
- links to VS-11.2/VS-46.2 (project/government), W918/W162/W793 (margin/bid/close), W4632 (revenue match)

## W4666. Service & Installation Costing (Labor, Subcontractor, Burden)

| Field | Detail |
|---|---|
| **Trigger** | Service/installation sale (VS-12); service cost transaction; periodic refresh |
| **Frequency** | Per service type + periodic |
| **Volume** | Installation & repair services (VS-12.1); tool rental; workshops |
| **Owner** | Cost Accounting Manager |
| **Participants** | Services (VS-12), HR/Labor (VS-19), Subcontractor mgmt, Controller |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Build the service-cost standard: direct labor (loaded wage rate incl. benefits/burden per VS-102), subcontractor rate, vehicle/tool cost, and service overhead; allocate to the service work order (W544) | Cost Accounting / Services / HR | Controller | Per service type |
| 2 | Collect actual service cost (technician timesheet, subcontractor invoice, vehicle/tool cost) to the work order; post service-cost variance (actual vs. standard) | Cost Accounting / Services | Controller | Per work order + monthly |
| 3 | Analyze service margin by service type/technician/region; feed into service pricing (VS-12) and the performance-obligation allocation for product+install bundles (W4627/W4634) | Cost Accounting / Services | Controller | Quarterly |

### System Touchpoints
- Service work order (W544); payroll/labor (VS-19.2/VS-102); subcontractor AP (VS-15); GL (VS-17.1)

### Pain Points / Risks
- **Under-burdened-labor risk**: Labor cost without benefits/burden understates service cost and overstates service margin; mitigated by the loaded-rate build (VS-102)
- **Subcontractor-cost-miss risk**: Subcontractor invoices not captured to the work order; mitigated by WBS/work-order-driven collection

### Time Estimate
- ~per service type 2–4 hours; ~2–3 days/month service-cost variance

### Automation Opportunity
- Loaded-labor-rate engine; timesheet-to-work-order auto-collection; service-margin dashboards

### Controls
- CTL: service cost built with loaded labor burden; actual collected to work order; variance analyzed monthly

### Cross-references
- links to VS-12 (services), W544 (work order), VS-102 (comp/burden), W4627/W4634 (bundle allocation)

| Field | Detail |
|---|---|
| **Trigger** | Intercompany service/goods flow (VS-72); transfer-pricing review (VS-17.2) |
| **Frequency** | Per IC flow + quarterly TP review |
| **Volume** | 5-entity group; warehousing/distribution fees, ecommerce fulfillment fees, rent (VS-97) |
| **Owner** | Cost Accounting Manager |
| **Participants** | Intercompany/Shared Services (VS-72), Treasury (VS-18), Tax (VS-79), Controller |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Build the intercompany cost-transfer model: the cost-plus markup for BuildRight Logistics warehousing/distribution fees to Depot Inc., Digital Commerce per-order fulfillment fees, and Property Mgmt rent (at arm's-length transfer pricing per VS-17.2 W612/W1299) | Cost Accounting / Shared Services | Controller / VP Tax | Per IC flow |
| 2 | Compute the cost base for each IC service (actual operating cost of the serving entity + agreed markup); post IC cost to the receiving entity and IC revenue to the serving entity; eliminate on consolidation (VS-17.2) | Cost Accounting / IC | Controller | Monthly |
| 3 | Validate transfer-pricing alignment (arm's-length) with TP documentation (VS-17.2 W1299/VS-72 W2594); adjust markups on the annual TP review and post IC reclass | Cost Accounting / Tax / Treasury | Controller / CFO | Quarterly + annual |

### System Touchpoints
- Intercompany module (VS-72); transfer-pricing rules (W305/W612/W1299); GL (VS-17.1); consolidation (VS-17.2)

### Pain Points / Risks
- **Non-arm's-length risk**: IC markups not at arm's-length → BIR transfer-pricing exposure (VS-79/VS-17.2); mitigated by TP documentation and annual review
- **Cost-base distortion risk**: An inaccurate serving-entity cost base produces wrong IC fees; mitigated by the cost-base build and reconciliation

### Time Estimate
- ~per IC flow 2–4 hours; ~3–5 days/quarter IC/TP accounting

### Automation Opportunity
- IC cost-transfer engine from serving-entity actual cost; auto-elimination on consolidation; TP-alignment dashboard

### Controls
- CTL: IC markups arm's-length (TP-documented); cost base reconciled; eliminated on consolidation

### Cross-references
- links to VS-72 (IC/shared services), VS-17.2 (consolidation/TP), W305/W612/W1299 (TP rules), VS-97 (rent)

## W4668. Consignment & VMI Cost-Basis & Margin-on-Sell-Through

| Field | Detail |
|---|---|
| **Trigger** | Consignment/VMI sell-through (VS-45); monthly settlement |
| **Frequency** | Per sell-through + monthly |
| **Volume** | ~300 VMI/consignment SKUs from 12 vendors |
| **Owner** | Cost Accounting Manager |
| **Participants** | Merchandising (VS-45), Vendor Mgmt (VS-03), Controller, Revenue Accounting (VS-157) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Establish the consignment/VMI cost basis (vendor settlement price at sell-through, not at receipt — goods are vendor-owned per VS-45.1); confirm BuildRight as principal (gross) for the consumer sale (W4628) | Cost Accounting / Merchandising | Controller | Per setup |
| 2 | At each sell-through (W543), post COGS at the consignment cost basis and the AP/vendor-payable at settlement; recognize revenue per W4629 | Cost Accounting / AP | Controller | Per sell-through |
| 3 | Compute consignment/VMI margin (sell-through price − cost basis) by SKU/vendor; reconcile to the vendor settlement (VS-45.3); monitor commission/fee-type consignment where BuildRight is agent (net) | Cost Accounting | Controller | Monthly |

### System Touchpoints
- Consignment/VMI module (VS-45); sell-through feed (W543); vendor settlement (VS-45.3); GL (VS-17.1); revenue (W4629)

### Pain Points / Risks
- **Cost-at-receipt error risk**: Booking consignment cost at receipt (as if purchased) mis-values inventory and cost; mitigated by the cost-at-sell-through rule
- **Settlement-reconcile risk**: Cost basis vs. vendor settlement mismatch distorts margin; mitigated by the monthly reconcile (W4629)

### Time Estimate
- ~2–3 days/month consignment/VMI cost accounting

### Automation Opportunity
- Sell-through-triggered COGS + vendor-payable auto-post; cost-basis-to-settlement auto-reconcile

### Controls
- CTL: consignment cost at sell-through (not receipt); principal/agent posture documented; reconciled to settlement monthly

### Cross-references
- links to VS-45 (consignment/VMI), W543 (sell-through), W4628/W4629 (principal/recognition), VS-45.3 (settlement)

## W4669. Cost-Accounting Calendar, Period Close & Cost Allocation Cycles

| Field | Detail |
|---|---|
| **Trigger** | Cost-accounting calendar; period close |
| **Frequency** | Monthly (+ weekly flash for volatile categories) |
| **Volume** | 5 entities × 12 months; multiple allocation cycles |
| **Owner** | Cost Accounting Manager |
| **Participants** | Controller, GL/Close (VS-17.1), DC Ops (VS-04), HR (VS-19) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Maintain the cost-accounting calendar aligned to the fiscal close (W9A/W9B): standard-cost roll, landed-cost run, freight/duty allocation, overhead absorption, variance analysis, NRV review — sequenced with dependencies | Cost Accounting / GL | Controller | Per calendar |
| 2 | Execute the cost-allocation cycles each period: freight/handling to SKU (W4652), overhead to product/service, labor to service/project (W4666), IC cost transfer (W4667); post and reconcile each cycle | Cost Accounting | Controller | Per close |
| 3 | Validate the cost close before financial-close sign-off: all variances posted, COGS reconciled (W4663), margin pack produced (W4661); resolve exceptions | Cost Accounting / GL | Controller | Per close |

### System Touchpoints
- Close calendar (VS-17.1 W9A/W9B); allocation engine; variance ledgers; GL (VS-17.1)

### Pain Points / Risks
- **Cycle-sequence risk**: Allocation cycles run out of order (e.g., freight allocated before landed-cost finalized) → incorrect costs; mitigated by the sequenced calendar with dependencies
- **Late-exception risk**: Exceptions discovered after financial close require re-open; mitigated by pre-sign-off validation

### Time Estimate
- ~5–7 days/period cost close (absorbed in the close cycle)

### Automation Opportunity
- Dependency-aware cost-close orchestration; pre-sign-off exception gate

### Controls
- CTL: cost calendar sequenced with dependencies; allocation cycles posted and reconciled; close validated before sign-off

### Cross-references
- links to W9A/W9B (close), W4652/W4666/W4667 (allocations), W4663/W4661 (reconcile/margin)

|---|---|
| **Trigger** | Cost-master change request; audit finding; governance review |
| **Frequency** | Per change + quarterly governance review |
| **Volume** | ~35K SKU cost records; vendor/contract cost data |
| **Owner** | Cost Accounting Manager |
| **Participants** | Master Data (VS-29), Merchandising (VS-01), Controller, Internal Audit (VS-21) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Govern cost-master data (cost elements, conversion factors, allocation bases, overhead rates, kit/BOM) through the master-data governance process (VS-29): request, validate, approve, post, audit-trail | Cost Accounting / Master Data | Controller | Per change |
| 2 | Apply the cost-change approval matrix: standard-cost change tiered approval (Category Mgr → Controller → CFO by materiality); segregate those who request a cost change from those who approve and post | Cost Accounting / Controller | CFO | Per change |
| 3 | Review cost-master data quality quarterly (completeness, accuracy, timeliness); remediate data-quality issues and feed into the data-quality scorecard (VS-29 W291) | Cost Accounting / Master Data | Controller | Quarterly |

### System Touchpoints
- Master data governance (VS-29); cost-master (W4649); data-quality monitoring (W291); audit trail (VS-88)

### Pain Points / Risks
- **Ungoverned-change risk**: A cost-master change bypassing governance (e.g., a buyer editing a cost) corrupts the cost layer; mitigated by the governance + SoD
- **Data-quality-decay risk**: Stale/incomplete cost data degrades margin analytics; mitigated by quarterly data-quality review

### Time Estimate
- ~per change absorbed; ~3–5 days/quarter governance review

### Automation Opportunity
- Cost-change workflow with tiered approval + SoD; data-quality scorecard feed; change-audit-trail

### Controls
- CTL: cost-master changes via governance with tiered approval and SoD; data-quality reviewed quarterly

### Cross-references
- links to VS-29 (master data), W291 (data quality), W4649 (cost-master), VS-21 (audit), VS-88 (records)

## W4672. Cost-Accounting Internal Controls, Variance-Threshold & SoD Governance

| Field | Detail |
|---|---|
| **Trigger** | Risk assessment; audit; control remediation; annual review |
| **Frequency** | Continuous + annual review |
| **Volume** | 1 cost-accounting control set across 5 entities |
| **Owner** | Cost Accounting Manager / Controller |
| **Participants** | Internal Audit (VS-21), Revenue Assurance (VS-118), IT Security (VS-27.3), Controller |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Maintain the cost-accounting control set: preventive (cost-change approval matrix W4670, config sign-off W4671, cost-at-sell-through rule W4668) and detective (variance-threshold investigation W4657/W4658/W4659, COGS reconcile W4663, NRV review W4660); map to the internal-controls matrix | Cost Accounting / Internal Audit | Controller | Annual + continuous |
| 2 | Enforce segregation of duties: those who set standard cost, those who post cost journals, and those who reconcile/variance-investigate are separate; restrict manual cost-adjustment authority | Controller / IT Security | CFO | Continuous |
| 3 | Preserve the cost-change and variance audit trail for 10 years (BIR/audit); coordinate with Revenue Assurance (VS-118) on margin-leakage investigation spanning cost and revenue | Cost Accounting / Internal Audit | Controller | Continuous |

### System Touchpoints
- Internal-controls matrix (VS-21); audit trail (VS-88); SoD roles (VS-27.3); ERP journal history

### Pain Points / Risks
- **Cost-manipulation risk**: Manual cost-adjustment authority mis-used to manage margin; mitigated by SoD, restricted authority, and audit trail
- **Control-coverage gap risk**: A control missing for a new cost flow/category; mitigated by the annual control review tied to the cost-master

### Time Estimate
- ~5–8 days/year control-set maintenance; continuous SoD/audit-trail

### Automation Opportunity
- SoD-conflict detection; manual-cost-adjustment log analytics; control-coverage report tied to cost-master

### Controls
- CTL: documented control set mapped to internal-controls matrix; SoD enforced; audit trail retained 10 years; controls reviewed annually

### Cross-references
- links to VS-21 (internal audit), VS-118 (revenue assurance), VS-27.3/VS-88 (security/records), W4657/W4660/W4663 (operating controls)
